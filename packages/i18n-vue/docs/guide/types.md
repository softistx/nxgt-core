# Types

`t` is typed from a declaration file generated from your catalogues. With
it, the editor completes `t('home.` and the type checker — `tsc` for code,
`vue-tsc` for templates — refuses a key that does not exist and an argument
that cannot be right. Without it, `t` takes any string and any arguments, and
the checks happen only when `t` runs.

## With Vite

```ts
// vite.config.ts
import vue from '@vitejs/plugin-vue';
import { i18nTypes } from '@nxgt/i18n-vue/vite';
import { defineConfig } from 'vite';

export default defineConfig({
	plugins: [vue(), i18nTypes({ locales: ['en', 'fr'] })],
});
```

```gitignore
# .gitignore
src/generated/
```

```jsonc
// tsconfig.json — the file must be in the program; src/** already covers it
{ "include": ["src/**/*.ts", "src/**/*.vue", "src/**/*.d.ts"] }
```

The plugin writes `src/generated/i18n.d.ts`:

- when `vite dev` or `vite build` starts — a catalogue that cannot be right
  **fails** it, naming the locale and the key;
- in `vite dev`, each time a `<locale>.json` in `dir` is added or changed. A
  change that breaks a catalogue is logged, and the last good types are
  kept; the app's own `createI18n` then refuses the catalogue in the browser.

In CI, run `vite build` (or any command that starts Vite) before `vue-tsc`,
so the file exists.

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `locales` | `readonly string[]` | — (required) | Every locale, as BCP 47 tags |
| `fallbackLocale` | `string` | the first locale | The catalogue the types are written from |
| `dir` | `string` | `'locales'` | The folder of `<locale>.json`, from Vite's `root` — and of `<locale>/**/*.json`, a folder file's path a key prefix. Not with `messages` |
| `messages` | `string` | — | A module whose default export is the resources object, or a function that returns it — instead of `dir`. Not with `dir` |
| `catalogues` | `readonly Catalogues[]` | `[]` | Catalogues a package ships, merged under yours ([Catalogues](catalogues.md#catalogues-from-a-package)) |
| `out` | `string` | `'src/generated/i18n.d.ts'` | The file written, from Vite's `root`. It must end in `.d.ts` |

See [Splitting catalogues](catalogues.md#splitting-catalogues) for the folder
layout and `messages`.

The plugin never replaces a file it did not write: if `out` holds something
that `typesSource` did not write — its first line `// Generated by …`, its
second the line every generated file carries — it throws and leaves the file
alone.

## What the file says

```ts
// src/generated/i18n.d.ts
// Generated by @nxgt/i18n-vue from the en catalogue.
// Never edited, never committed: it types t() from the catalogues.
import type {} from '@nxgt/i18n-vue';

declare module '@nxgt/i18n-vue' {
	interface I18nMessages {
		'home.greeting': { name: string | number };
		'home.items': { count: number };
		'home.sent-on': { at: Date | number };
		'home.sentOn': { at: Date | number };
		'home.title': { };
	}
	interface I18nLocales {
		'en': true;
		'fr': true;
	}
}
```

A key gets both spellings — a catalogue written `sentOn` also types
`sent-on`, and one written `sent-on` also types `sentOn` — so `t()` completes
and checks either, whichever convention the catalogue happens to use (see
[Catalogues](catalogues.md#keys-are-kebab-case-or-camelcase-and-nested)).

`I18nMessages` gives each key its arguments, `I18nLocales` the locales.
From them:

| Type | Is |
| --- | --- |
| `MessageKey` | `'home.greeting' \| 'home.items' \| …`, or `string` with no file |
| `Locale` | `'en' \| 'fr'`, or `string` with no file |
| `MessageArgsOf<'home.items'>` | `[args: Readonly<{ count: number }>]` |

## What is refused

In a template, as in code:

```vue
<template>
	{{ t('home.title') }}                          <!-- ok -->
	{{ t('home.greeting', { name: 'Ada' }) }}      <!-- ok -->
	{{ t('home.sent-on', { at: new Date() }) }}    <!-- ok — sentOn's other spelling -->
	{{ t('home.titel') }}                          <!-- not a key -->
	{{ t('home.greeting') }}                       <!-- { name } is missing -->
	{{ t('home.title', { name: 'Ada' }) }}         <!-- home.title takes no argument -->
	{{ t('home.items', { count: '2' }) }}          <!-- count is a number -->
	{{ t('home.sentOn', { at: 'today' }) }}        <!-- at is a Date or a timestamp -->
</template>
```

```ts
setLocale('de'); // not a locale of the catalogues
i18n.locale.value = 'fr'; // read-only: use setLocale
```

A key that may be one of several (`ok ? 'a' : 'b'`) takes the arguments
every one of them accepts, so both must take the same names:

```vue
{{ t(ok ? 'home.title' : 'home.action') }}   <!-- ok: neither takes an argument -->
{{ t(ok ? 'home.title' : 'home.items') }}    <!-- refused: one needs { count } -->
```

A key typed as any message (`key as MessageKey`) takes any arguments; `t`
checks them when it runs.

## Without generated types

`createTranslator` can take its keys from the catalogue's own type, with
`CatalogueKey`, built on a `Path` utility this package carries itself — the
one thing it ever took from `@nxgt/i18n`, inlined so installing
`@nxgt/i18n-vue` never requires `@nxgt/i18n` too. That types the keys, not
the arguments:

```ts
import { type CatalogueKey, createTranslator } from '@nxgt/i18n-vue/core';
import en from './locales/en.json';

const t = createTranslator<CatalogueKey<typeof en>>({ en, fr }, 'en');
t('home.title'); // ok
t('home.titel'); // refused
```

## Another build

`@nxgt/i18n-vue/vite` exports the pieces `i18nTypes` is made of, for a build
that is not Vite:

```ts
// scripts/i18n-types.ts
import { loadCatalogues, typesSource, writeTypes } from '@nxgt/i18n-vue/vite';

const root = process.cwd();
const loaded = await loadCatalogues(root, { locales: ['en', 'fr'] });
writeTypes(
	`${root}/src/generated/i18n.d.ts`,
	'src/generated/i18n.d.ts',
	typesSource(loaded.reference, loaded.fallbackLocale, { locales: loaded.locales }),
);
```

`typesSource` can fill another module's interface — `module`,
`messagesInterface` and `generator` options — for a package that declares
its own.

## Type safety is measured

The package's own tests hold what the types refuse:
`test/types/refusals.ts` has **21** mistakes in TypeScript and
`test/types/refusals.vue` **7** in a template, checked by `vue-tsc` against a
generated file; the Nuxt fixture adds **3** under Nuxt's own `tsconfig`. Each
is an `@ts-expect-error` or `@vue-expect-error`, so a refusal that stops
holding fails the typecheck. The calls that must keep compiling sit beside
them.

## Under Nuxt

The module writes the same file to `.nuxt/types/nxgt-i18n-vue.d.ts`, which
Nuxt's generated `tsconfig` already includes. Nothing to configure; run
`nuxt prepare` (Nuxt's `postinstall`) before `vue-tsc`. See [Nuxt](nuxt.md).
