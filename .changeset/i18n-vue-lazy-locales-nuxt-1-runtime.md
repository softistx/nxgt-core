`@nxgt/i18n-vue/nuxt/runtime` adds `setupLazyNuxtI18n(context): Promise<I18n>`, `LazyNuxtI18nContext` and `CATALOGUE_STATE_KEY` (`'@nxgt/i18n-vue:catalogue'`), for a Nuxt plugin whose locales are loaded on demand. The locale is resolved as `setupNuxtI18n` resolves it (the state, the cookie, the requested languages, the fallback locale), among `locales`; a locale of `loaders` is loaded before the promise resolves, so the server renders in it, and the catalogue it rendered in travels in the payload (`useState(CATALOGUE_STATE_KEY)`), so the browser hydrates in it without calling the loader. A `setLocale` writes the state, the cookie and the catalogue state together, so `await setLocale(locale)` on the server renders and hydrates in it; a locale guessed from `Accept-Language` is still never written to the cookie. A loader that rejects while the locale is resolved rejects the setup with `setLocale: the catalogue of <locale> could not be loaded`. A catalogue a loader answers stays on `createI18n`'s `loaders` path and is never cached per request, so a loader that answers a new object each time does not grow a server's memory. A `locales` entry in neither `catalogues` nor `loaders` is refused up front with the `TypeError` `setupLazyNuxtI18n: locales holds <locale>, which is neither in catalogues nor in loaders — give each locale a catalogue or a loader`. `setupNuxtI18n` is unchanged.
