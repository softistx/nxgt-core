**`setLocale` now returns `Promise<void>` instead of `void`.** A call that ignores the result behaves exactly as before: a locale of `catalogues` switches synchronously and the promise is already resolved. Only code that implements the `I18n` interface by hand (a test double, a wrapper) has to return a promise from its `setLocale`.

`createI18n` takes an optional `loaders` record, `{ fr: () => import('./locales/fr.json') }`, to load a locale's catalogue on demand: the first `setLocale` to it runs the loader, checks the catalogue against the fallback locale, and switches once both are done, keeping `locale` and `t` on the previous locale meanwhile. The last call wins: a superseded call resolves without switching when its load succeeds, and still rejects when it fails. A locale has one load in flight at a time, and a failed load is retried on the next call. A module namespace is unwrapped to its default export when its `Symbol.toStringTag` is `'Module'`, or when it mirrors its default export (every other key the same value as `default`'s, as a bundle without splitting answers); a plain `{ default: {...} }` stays a catalogue. It is plain `import()` and needs no plugin: Bun, Vite, webpack and esbuild import JSON as is, and plain Node ESM with `{ with: { type: 'json' } }`. Without `loaders`, nothing changes. New exports: the `CatalogueLoader` and `CatalogueLoaders` types. New errors: `setLocale: the catalogue of <locale> could not be loaded` (with the loader's error as `cause`), `setLocale: the loader of <locale> must answer a catalogue, or a module whose default export is one`, and four `createI18n: …` `TypeError`s for a wrong `loaders`, raised only when `loaders` is given.
